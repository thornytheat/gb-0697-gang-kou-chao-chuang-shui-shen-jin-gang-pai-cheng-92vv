# 潮窗字段

CSV 表头固定为 `id,station,kind,start,end,value,aux,version,unit`，UTF-8（可带 BOM）或 GB18030。id 保持字符串。

## 验潮站 station

`station` 是潮位记录（kind=tide）的强制字段，取值来自站点登记 `app/stations.py`：

| 编号 | 名称 | 名义潮时差 | 角色 |
|---|---|---|---|
| OFFSHORE | 外海验潮站 | 0（基准） | 必备 |
| HARBOR | 内港验潮站 | +1800 秒（滞后半小时） | 必备 |
| OUTER_ANCHOR | 第三站（锚地） | 0 | 旁证，未回传不阻断发船 |

非潮位记录（ship/pilot/block）station 留空。未知或缺失站点编号隔离为 `STATION`，不并入任何曲线。

## 多站采信，不再合并成一条曲线

- 各站独立成线，分别按时间排序、分段线性插值；相邻观测超过 3 小时的缺口不外推。
- 同一时刻**跨站**读数不同属于正常潮时差，不再判 `TIDE_TIME_CONFLICT`。冲突只在**同一站内部**判定：同站同时刻不同值全部隔离；同值重复仅保留编号最小者。
- 安全水深取当时各可用站的**包络（最小值）**：任一站不达标即不开窗，避免读数偏高的站把船放进不够深的时段。
- 采信等级：`CONFIRMED` 三站齐备；`PROVISIONAL` 两必备站在但缺第三站；`WEAK` 连必备站都缺（不外推）。临时窗可发船但禁止自动通过，须人工复核。
- 每个安全窗与逐时刻时间轴都记录采信站、缺证站、各站来源物理行号，缺口原因写明“未回传或观测缺口，不外推”。

## 潮时差核对

按高/低潮转折点配对外海与内港，实测滞后与名义 1800 秒比较；偏差超过 5 分钟（`LAG_TOLERANCE_S`）标 `within_tolerance=false`，结果在 M3 与导出中可查。系统只登记偏差，不擅自平移读数。

## 其余字段

kind 取 tide、ship、pilot、block。start/end 带时区；统一 UTC 秒。tide 的 value 为潮高；ship 为吃水；m/cm 统一为 m。ship 的 aux 为通航分钟。version 为递增版本，采用同 (kind,id) 最高版；同 (station,kind,id,version) 多条隔离。

基准水深 8m，安全余量 1m，要求潮高>=吃水+1-8。航道区间为半开，结束同刻可开始下一航次。引航窗口须覆盖整个航次。排程按最早申请时间、船舶ID确定先后，优先确认窗、其次临时窗，同级取最早可行窗。并非全局最优调度。

## 读数更正与批次失效

同一验潮站同一时刻出现更高 version 读数即一次读数更正（`tide_corrections`）。读数更正后原安全窗失效：新批次通过 `run_links` 登记它取代了哪些采信过该站该时刻旧读数的批次，旧批次决策置为“已失效-读数更正”。同一输入内容（含规则版本）摘要恒定，重跑复用同一批次，绝不重复建批。
